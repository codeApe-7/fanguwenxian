# 《凡骨问仙》剧情引擎与文案设计

> 0.6 版底层文案与剧情全面重做的设计说明。
> 核心思路：**剧情不靠写得多，靠调度得好**——世界有自己的时间线，
> 窗口会关，选择留痕，失败也是叙事。本文档同时是文案写作规范与扩展指南。

---

## 1. 诊断：旧版缺的不是文案量，是调度层

| 旧版（≤0.5.x） | 问题 |
| --- | --- |
| 每剧本 5 段 beat，`age >=` 触发，下标单调递增 | 主线 50 岁播完，此后 6 个大境界零剧情 |
| 怎么玩都能看完全部剧情 | 无取舍，无二周目动力 |
| 选择只改数值，无 flag | 「坠魔/渡魔」这种大抉择，下游文案一字不差 |
| 剧情永不失败、永不错过 | 「没做到」这一整类叙事不存在 |
| 一段 text 兼任世界描述/指路/叙事 | 加节点=重写整段，扩展成本高 |
| 性格只影响好感数值 | 八种性格一个措辞，无人物辨识度 |

0.6 版重做的就是这一层：**内容不变薄，调度变厚。**

---

## 2. 总体架构

```
src/content/            内容层（数据 + 文案，可独立增删）
  story.ts              主线节点库：4 剧本 ×12 节点 + 7 共用系统节点
  world.ts              纪元（玄启）、起始年、地点池（{place} 取值域）
  dialogue.ts           性格×场景对白矩阵（8 性格 × 13 场景）
  letters.ts            传音信件库（条件 + 延迟 + 效果/流程）
  tasks.ts              宗门任务库（三层文案 + 冷却 + 境界窗）

src/core/               调度层（何时、给谁、放不放）
  storyline.ts          主线调度器：窗口判定 / flag / 错过归档与播报
  chronicle.ts          世界纪事（周期+一次性大事）+ 传音投递管道
  combat.ts             战斗类型（FoeKind / 擂台 / 连战 carry）+ 双血条面板
  text.ts               fill 占位符、«»高亮、纪年格式化、大事记(addBio)
```

主循环（engine.ts）每过一年依次结算：
`yearEnd`（数值年结）→ `worldTick`（世界大事+传音）→ `maybeTriggerStory`（主线，每年至多一节点）。

## 3. 核心机制

### 3.1 世界纪年（state.year）

- 纪元「玄启」，开局＝玄启 102 年（主角 16 岁）。世界大事挂在**绝对纪年**上，
  不围着玩家年龄转：玄启 120 年魔乱必然爆发，你那时是筑基还是元婴，是你自己的节奏造成的。
- 状态栏常驻「下一大事」提示（`nextWorldEvent`），让**等待与闭关有指向**：
  「再熬三年就是拍卖大会」。

### 3.2 主线节点（StoryNode）

```ts
{
  id: '凡骨·荒涧古府',
  scenario: '天命凡骨',        // 缺省 = 全剧本共用
  minAge / maxAge,             // 年龄窗
  minRealm / maxRealm,         // 境界窗（双向！冲太快也会错过）
  require: [{ flag: '骨片' }], // flag 前置（op: '>=' | '<' | '='）
  exclude: ['终章'],           // 互斥 flag
  when: (state) => …,          // 系统条件（丹毒/道侣/宗主/叛逃/寿元）
  text / choices / effects,    // 叙事与分支（choices 可挂真实战斗）
  missText: […],               // ★ 错过反馈：关窗当年播报一次
  log: '…',                    // 大事记条目
}
```

调度规则（core/storyline.ts）：

1. **每年至多触发一节点**；剧本专属节点优先于共用节点，数组顺序即同年优先级。
2. **错过归档**：`maxAge`/`maxRealm` 一过即永久错过。仅在「刚刚错过」
   （年龄=上限+1 或 境界=上限+1）时播报 missText——旧档迁移的陈年错过静默归档，不刷屏。
3. **flag 是记忆**：选择写 flag，几百年后的节点用 require/exclude 读它。
   四个剧本的渡劫期终章都是多变体互斥节点（共享「终章」flag），按一生的路各自收束。
4. `when` 节点让已有系统进入叙事：丹毒≥60 走火剧情、道侣好感≥90 护关剧情、
   宗主抉择、叛逃岁月、寿数将尽——**系统层不再游离于故事之外**。

### 3.3 世界纪事（chronicle.ts）

| 类型 | 事件 | 节拍 |
| --- | --- | --- |
| 周期 | 青崖英杰会（限«筑基以下、60 岁内»） | 每 5 年，自玄启 105 |
| 周期 | 四海拍卖大会（法宝/突破丹折价） | 每 10 年，自玄启 108 |
| 周期 | 甲子灵潮（闭关 +20% ×5 年） | 每 60 年，自玄启 132 |
| 一次 | 玄阴魔乱（正/避/枭三选，站队留 flag） | 玄启 120–135 |
| 一次 | 沉星海眼（**双向境界窗**：仅«结丹~化神»可入，仙品残篇来源） | 玄启 150–185 |
| 一次 | 天门虚影（«合体以上»观礼，渡劫成功率 +5%） | 玄启 235–260 |

- 英杰会对「急着筑基还是再拿一届」构成真实取舍；海眼对「冲太快」的人关门——
  **修炼速度与剧情覆盖率互相拉扯**，这是修仙题材「长生与机缘不可兼得」的玩法表达。
- 一次性大事关窗次年播报错过反馈并记入大事记。

### 3.4 传音投递（letters.ts）

剧情**主动找玩家**，而非等玩家翻菜单。每封信：

- **条件**（好感/境界/宗门/flag/系统状态）×**随机延迟**（同批条件满足不同年送达，
  体感是「陆陆续续有人找我」而非「系统在结算」）×**唯一性**×**每年至多一封**。
- `forLead` 信件按每位红颜实例化，开场白自动经性格矩阵取措辞。
- 内容含抉择（红颜求援：驰援/不救，各有后果与 flag）、宗门嘉勉、亡命暗信、
  昭衡司谢函、江湖战书等 9 类。

### 3.5 性格×场景对白矩阵（dialogue.ts）

同一语义场景，按性格查表取措辞——**用一份事件逻辑做出八种人物**：

- 8 性格（清冷孤傲/温婉贤淑/活泼灵动/腹黑狡黠/坚韧倔强/洒脱不羁/外冷内热/古灵精怪）
  × 13 场景（邂逅/拜访开场/交谈/论道/赠礼受与拒/好感 40 与 70 里程碑/结缘/双修/重逢/来信/获救）。
- 好感 40/70 里程碑是一次性小剧情（`lead.seen` 去重），互动跨过阈值时触发。
- 接线点：romance.ts（全部互动）、explore/events（邂逅/重逢/搭救）、letters（来信口吻）。

### 3.6 宗门任务：三层文案 + 决策含量（tasks.ts / sect.ts）

每个任务三层分离，结构与叙事解耦：

| 层 | 字段 | 长度 | 职责 |
| --- | --- | --- | --- |
| 指路层 | `step` | ≤16 字 | 菜单一行，「干什么」 |
| 世界层 | `world` | 数十字 | 告示：这件事在世界里是什么（**无主角视角**） |
| 人物层 | `say` | 一句 | 执事口吻，`{daoyou}` 按职阶称呼、`{place}` 地点池 |

决策含量三件套：

1. **失败扣贡献**（战斗任务败 = −奖励/4）+ 专属失败文案（`failSay`，按难度分档语气）——接了不做有代价，「接哪个」才是决策；
2. **冷却**（1–6 年）——防刷单一任务；
3. **境界窗**——低阶杂役到高境界自动下架（「真人不巡山」），高阶要务（镇守大阵）需«结丹以上»。

### 3.7 战斗类型与战斗面板（combat.ts）

> 0.7 版战斗层已大幅扩写（灵气 / 后继无力 / 五行三乘区 / 效果组合 / 渡劫两场真战斗），
> 完整说明见 [战斗与数值设计.md](战斗与数值设计.md)；本节只留与剧情调度相关的部分。

战斗不是一个通用函数，是**有类型的场合**。同一份战斗逻辑，靠 `CombatOpts` 分出擂台与厮杀：

| 字段 | 作用 |
| --- | --- |
| `kind: FoeKind` | 敌人取名池：妖兽 / 修士 / 魔修 / 天骄 / 同门。天骄与同门走 `randomFoeName()` 生成人名（境界高则带道号） |
| `foe` | 指名道姓的对手（现任宗主、无名剑客、守府铁傀），优先于 `kind` |
| `arena: '擂台' \| '切磋'` | **点到为止**：不夺灵石、不掉战利品、「逃跑」变「认输」、败只是被震落擂台 |
| `carry: {hp}` | **连战气血延续**：以此开局，战后写回。大比三轮轮间 +30% 上限调息，宗门战争三阵只 +10% |
| `title` | 面板顶栏（「宗门大比 · 第一轮」） |

**为什么要分池**：一个池子打天下，就会写出「与你对阵的同辈天骄——正是碧鳞妖蟒」。
场合决定对手，这是最廉价也最见效的沉浸感来源。法宝掉落同理——只从「人」身上缴获，妖兽身上摸不出一柄剑。

界面每回合整屏重绘一块 46 列面板：敌我双血条（含上限）+ 携带资源 + 最近四条战报，
不再逐行往下刷屏。非 TTY 环境（QA 脚本）`clear()` 是空操作，面板顺序堆叠，日志仍完整。

### 3.8 出身 × 经历的一致性（content.ts）

`OriginDef.tags`（孤儿/有家/富庶/清贫/书香/武门/仙门/魔道/市井/山野）×
`Talent.needTags/banTags` → `talentsFor(list, origin)` 过滤儿时/青年经历。

孤儿没有家世可败落，也不会有婚约可退。被过滤掉的条目**隐藏而非置灰**，
菜单末尾提示「另有 N 项经历与你的出生不符」——**未列出的东西本身就是换出身的理由**。
改出身时失效的经历自动退回中性缺省（「童年寻常」「平淡无奇」）并提示一句。
先天项（资质/体质/灵根）与出身无关，不参与过滤。

### 3.9 占位符与高亮（text.ts）

- `fill(tpl, ctx)`：`{name}/{her}/{place}/{town}/{daoyou}` 运行时填充——
  一套文案配不同地名/称呼，即可覆盖全境界全剧本，不必逐档重写。
- `«…»`：**旁白内关键信息高亮**（时间窗/境界条件/数量），旁白整行青色，«»内切黄。
  只用于 `io.narrate` 的文本；菜单用 colors.ts。
- `eraYear(y)` → 「玄启107年」。

### 3.10 人生大事记与结局收束

- `addBio(p, '…')` 全程记录：主线抉择、错过、突破、大机缘、结缘、宗门大事——
  格式「玄启121年（35岁）· 某事」。
- 结局（飞升/殒身/寿尽）输出整部**立传**；飞升前 `tribulationMods` 逐条结算一生
  抉择对天劫的影响（见天门/渡口/消业 增益，天忌/丹疾 减益），
  `epilogueLines` 按剧本 flag 输出 2–4 段收束文——**同一个终点，各人各有一篇传**。

## 4. 文案写作规范

1. **世界层不写「你」**。告示、大事的 world 文本描述世界本身，玩家没参与也成立。
2. **指路短句 ≤16 字**，只说当前该干什么；叙事放正文，别塞进菜单。
3. **«»只标三样**：时间窗、条件（境界/年齿）、关键数量。一段至多一两处，多则失焦。
4. **错过文案必须点两件事**：失去了什么 + 为什么（太慢/太快/没资格）。
   「有些门，只在你弱小时敞开」比「事件已过期」有效一百倍。
5. **失败是剧情**：失败文案按难度分档语气（简单=打趣，普通=惋惜，困难=沉重），
   并且要有代价（扣贡献/好感/心境）。
6. **性格差异写在动作与留白里**，不靠语气词堆砌：清冷的人「指尖在匣上停了一停」，
   胜过说十句「她其实很感动」。
7. **选择的后果延迟兑现**。当下只给一行反馈，真正的回响放在几十年后的
   require/exclude 节点与结局收束里。
8. 半文半白，句子短，专名统一（玄启/昭衡司/百宝斋/阴风堡/浮玉旧墟/桓无涯/无生魔主）。

## 6. 扩展指南

**加一个主线节点**（content/story.ts）：

```ts
{
  id: '凡骨·新节点', scenario: '天命凡骨', title: '短标题',
  minRealm: 5, maxRealm: 6,            // 炼虚~合体窗口，冲过合体即错过
  require: [{ flag: '骨片' }],
  text: ['……'],
  choices: [{ label: '…', result: ['…'], effects: { flags: { 新抉择: 1 }, log: '大事记一笔' } }],
  missText: ['错过反馈——失去了什么、为什么。'],
}
```

放进 `STORY_NODES` 对应剧本段落即可，调度器自动接管。窗口节点务必写 missText。

**加一桩世界大事**（core/chronicle.ts `WORLD_EVENTS`）：周期给 `every+startYear`，
一次性给 `startYear+endYear`（+missText）；参与门槛用 `realmMin/realmMax/ageMax`。

**加一封传音**（content/letters.ts）：`when` 条件 + `delay` 区间；
简单信用 `text+effects`，带抉择/战斗的写 `run`。

**加一个宗门任务**（content/tasks.ts）：补齐 step/world/say/failSay 三层四段 + cd + 境界窗。

**测试**：smoke.test.ts 有结构断言（id 唯一、每剧本 ≥10 节点、窗口必配 missText、
任务三层齐全、每种出身的经历池 ≥8 且含中性缺省、天骄不会取到妖兽名、擂台落败不夺灵石、
连战气血写回），新增内容漏配会直接报红。`npx tsx playtest.ts [1-4]` 可全速自动通关
一局输出全程文本，`npx tsx selfplay.ts [1-4] righteous|dark normal|strong [宗门]` 走真实创角
流程并输出覆盖率统计，两者均用于文案 QA。

## 7. 边界与红线

- 本次借鉴的是成熟修仙游戏的**机制与数据结构思路**（时间轴、错过、投递、查表、分层）；
  **全部文案、人名、地名、事件均为本作原创**。

## 8. 数值层：已在 0.7 版重做

本文档列过的数值/战斗待办，**已全部在 0.7 版落地**，详见
[战斗与数值设计.md](战斗与数值设计.md)：

| 旧待办 | 0.7 的做法 |
| --- | --- |
| 同境界战斗胜率偏低 | 属性改指数曲线 + 比例减伤公式；实测同境界会用神通胜率 55~65%，越一个大境界 <5% |
| 每个大境界一层新机制 | 结丹金丹品质（灵根纯度封顶）/ 元婴灵机引擎（6 选 1）/ 化神入道流派（9 选 1） |
| 神通「后继无力」 | 连发同一式 ×[1, .6, .36, .2, .1]，换招即复原；再加五行相生【连击】与相克乘区 |
| 渡劫改带规则的战斗 | 心魔劫（镜像自己、禁丹药、心境给护罩）+ 九重雷劫（九回合、无视半数防御、撑住即飞升） |
| 闭关效率绑定洞府/灵脉 | 六档洞府，首尾差 10 倍，坊市可买地契 |

另外补上的（同版）：五行灵根值、遁速与神识两条属性、神通库扩到 71 式（每式带画面描写）、
悟道点与神通五级成长、小境界自动晋升、战斗类型规则开关（擂台禁丹药法器）、
**敌人 AI**（牌组 + 灵气 + 五行 + 条件权重抽样 + 家底倍率，难度分层为「妖兽＜散修＜天骄」）。
